## Business Problem Statement claim coverage

The Business Problem Statement should be treated as a set of claims to test or
qualify, not as evidence. The additions below ensure EDA and subsequent model
work do not overstate what the supplied data can establish.

| Business Problem Statement claim | Plan treatment |
| --- | --- |
| The unit is a “customer,” and customer-level predictions will be produced. | Q1 now explicitly confirms whether `SK_ID_CURR` is a customer, loan, or application key. The supplied dictionary calls it a sampled-loan ID, so a customer-level claim requires confirmation before delivery language is finalized. |
| The population is unbanked or has thin credit files. | Q15 **[BPS added]** separates measurable prior-credit coverage from the unmeasurable unbanked claim. |
| The outcome is “default risk.” | Q4 now validates the exact `TARGET` definition against this wording. The dictionary defines payment difficulty, with unspecified X/Y thresholds; it does not establish a conventional default definition. |
| Alternative data adds value beyond rigid rule-based scoring. | Q10, Q13, and Q17 assess available alternative-data candidates and validation readiness. Q16 identifies the missing incumbent-rule baseline needed to demonstrate improvement. |
| Approval rates will rise 8–12%, losses will fall 5–8%, processing time will fall, portfolio loss will be below 5.5%, and NIM will improve 1.2%. | Q16 **[BPS added]** specifies the missing baseline, decision, loss, pricing, and workflow data required to measure each claim. |
| The model will achieve AUC-ROC ≥ 0.78 and map probabilities to risk tiers. | Q17 **[BPS added]** checks label and validation readiness, plus the absent tier policy and decision economics. |

## Execution guardrails

- Use `application_train.csv` only for target-rate and target-association
  analyses. Test is for consistency and scoring-readiness checks, not outcome
  comparison.
- Fit bins, thresholds, imputations, encodings, and any feature transformations
  on train only; apply the locked definitions to test afterward.
- Report denominators, missingness, and sparse-category flags alongside every
  target rate. Do not interpret a small-group rate as a stable pattern.
- Do not treat univariate association as causation, a lending-policy rule, or
  model approval.
- Keep `SK_ID_CURR` as an identifier and `TARGET` as the label; neither is a
  candidate predictor. Keep protected characteristics and proxy-prone fields
  separate from ordinary feature exploration pending governance review.
